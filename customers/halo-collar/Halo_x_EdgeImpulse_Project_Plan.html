The Problem

Halo's dog activity classification model achieves 97.6% accuracy in the lab but drops to ~60% in the real world — a 37-point gap. The pipeline (Python → C conversion, STM32 inference) is verified correct. This is a train-test distribution mismatch, primarily driven by collar orientation variability, limited behavioral diversity in training data, and class taxonomy complexity across 8 activity categories.

Phase 1: Understand, Then Restructure

Weeks 1–16 · $66,500

These workstreams are not sequential — findings from each feed back into the others through multiple experiment-evaluate-refine cycles. The approach is: Analyze → Experiment → Evaluate → Refine → Repeat.

WS1: Pipeline & Inference Review

Weeks 1–3 · Est. 1–2 weeks effort
Map end-to-end windowing & inference flow
Validate firmware vs. offline pipeline consistency
Continuous-buffer test to isolate firmware vs. model gap
Document limits and handoff points

WS2: Orientation Assumption Validation

Weeks 1–5 · Est. 2–3 weeks effort
Quantify collar orientation impact across all 50 features
Field study with controlled rotation scenarios
Sensitivity analysis: which features break first
Explore rotation-invariant feature alternatives

WS3: Class Simplification & Data Strategy

Weeks 3–8 · Est. 3–6 weeks effort
Simplify taxonomy: 8 classes → core set (rest, walk, run, eat)
Evaluate minority classes (on_shelf: 847 samples, human_carry: 1,789)
Define real-world data collection protocol
Update labeling guidelines and quality process
Begin collection campaigns for breed/size diversity

WS4: Evaluation Framework Redesign

Weeks 5–8 · Est. 2–3 weeks effort
Define real-world KPIs (not just lab accuracy)
Build evaluation harness with confusion matrix tracking
Per-class precision/recall targets
Establish baseline on real-world test set

WS5: Application-Level Logic

Weeks 8–16 · Est. 2–4 weeks effort
Temporal smoothing design (multi-window gating)
Confidence thresholding for uncertain predictions
State machine for activity transitions
Reduce "random classification explosions" (head shaking etc.)

WS6: Model & Feature Exploration

Weeks 5–16 · Est. 4–8 weeks effort
Spatial rotation augmentation strategies
Architecture benchmarking: 1D CNN, TCN, Transformer
EON Tuner for hardware-aware architecture search
Augmentation strategy review (current two-level approach)
Per-class accuracy refinement for weak classes

Phase 1 Exit Criteria

Real-world accuracy at 80–85%, with clear identified path to 90%+. Orientation robustness measurably improved. Cloud-to-device parity validated. Simplified class taxonomy proven. Evaluation framework in place with real-world test harness.

Recommended Collaboration Tooling

🏆 Recommendation: GitHub Repository

Both teams are engineering-heavy and almost certainly already use GitHub. A shared repo gives you version-controlled project documentation, issue tracking, and universal access — no extra licenses needed.

  • Project plan & docs — Markdown files in the repo, versioned and diffable
  • Task tracking — GitHub Issues with labels per workstream (WS1–WS6), milestone tags per phase
  • Progress visibility — GitHub Projects (free kanban board) for visual status
  • Decision log — Use a DECISIONS.md file or GitHub Discussions
  • Meeting notes — Markdown in a /meetings directory, linked from issues
  • Data & model versioning — Can link to Edge Impulse Studio runs from issues

Why this wins: Everyone already has a GitHub account. No Notion access issues. External stakeholders (Halo) get invited to a single repo. Markdown is portable — if you ever need to move platforms, the content travels with you.
